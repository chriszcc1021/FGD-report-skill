# FGD HTML 报告格式参考

用于把已经整理好的 FGD Markdown 报告转成可直接打开、可截图、可导出 PDF 的单文件 HTML。这里沉淀的是通用版式和交付规则，不写入单次项目结论。

## 适用场景

- 用户要求“HTML 报告”“可视化报告”“网页报告”“高级一点”“信息清晰”。
- 已有结构完整的 Markdown 报告。
- 需要保留表格、证据、Next Step、PIC、评分 appendix。
- 需要多语言本地化页面。

## 页面结构

HTML 页面默认顺序：

1. 顶部品牌细线
2. 标题区
   - eyebrow：项目名 / FGD / Research Report
   - H1：报告标题
   - lead：一段简短说明
   - 元信息标签：例如市场、版本、证据语言、研究焦点
3. 右上角语言切换（如需多语言）
4. 横向 sticky 导航
   - 项目背景
   - 核心结论
   - 玩家分层对比
   - 具体反馈建议
   - Appendix
5. 正文报告
6. `具体反馈建议` 表格
7. Appendix 打分表

不要默认加入 `关键发现` 导航或章节。若 Markdown 中没有该章，HTML 不得自动加回。

## 视觉系统

使用 Garena 风格的克制配色，不使用渐变。

```css
:root {
  --brand-primary: #C0504D;
  --brand-secondary: #997E5A;
  --brand-dark: #4D4D4D;
  --brand-medium: #7F7F7F;
  --brand-light: #BFBFBF;
  --brand-bg: #E9D7D3;
  --brand-bg-alt: #F5F0EE;
  --brand-white: #FFFFFF;
  --brand-black: #333333;
}
```

页面基调：

- 页面底色：`#F5F0EE`
- 内容底色：白色
- 重点色：深红 `#C0504D`
- 辅助色：铜金 `#997E5A`
- 正文色：炭灰 `#4D4D4D`
- 分割线：暖灰浅线

禁用：

- 不使用 `linear-gradient` / `radial-gradient`
- 不使用装饰性光斑、气泡、bokeh
- 不做 marketing landing page
- 不把正文过度卡片化
- 不使用大面积高饱和背景

## 字体

默认 serif 报告风格：

```css
@import url('https://fonts.googleapis.com/css2?family=EB+Garamond:wght@500;600;700;800&family=Noto+Serif+SC:wght@400;500;600;700&display=swap');

:root {
  --font-display: 'EB Garamond', 'Noto Serif SC', 'Garamond', 'Georgia', serif;
  --font-body: 'EB Garamond', 'Noto Serif SC', 'Garamond', 'Georgia', serif;
}
```

如果外网字体不可用，回退到本地 serif 字体即可。中文、泰语、越南语等本地化页面必须保证可读性。

## 布局规则

- 页面最大宽度约 `1160px`。
- 标题区紧凑，首屏能看到正文开头。
- 导航使用横向 sticky nav。
- 正文使用白底报告容器、轻边框、轻阴影。
- 章节标题使用圆形编号，但不要过大。
- 表格放在横向滚动容器中，不能撑破页面。
- 不要让页面级出现横向溢出。

## 反馈表结构

`具体反馈建议` 必须保持表格结构。

默认表头：

```text
反馈模块 | 提及频度 / 玩家提及比例 | 反馈点 | Next Step | 玩家原话 | 研发 PIC | 运营 PIC
```

默认不加：

```text
涉及地区 | 地区差异说明
```

表格规则：

- 桌面端优先一页内完整显示宽度；必要时表格容器内横向滚动。
- `提及频度 / 玩家提及比例` 表头必须换行。
- `运营 PIC` 可以换行显示为 `运营<br>PIC`。
- `玩家原话` 列可以使用更小字号，保证信息密度。
- `Next Step` 列必须整列统一浅暖黄底，不随隔行底色变化。
- `Next Step` 文本需要更高对比度、清晰行高和标签层级。
- `研发 PIC` / `运营 PIC` 列固定保留，可留空。

推荐列宽（单页清晰优先，可按内容微调）：

- `反馈模块`: 8-10%
- `提及频度 / 玩家提及比例`: 10-12%
- `反馈点`: 18-22%
- `Next Step`: 15-18%
- `玩家原话`: 28-34%
- `研发 PIC`: 5-7%
- `运营 PIC`: 5-7%

## 标签规则

### 频度标签

- 高频：深红字 + 浅红底
- 中频：铜金字 + 浅金底
- 低频：灰/蓝灰字 + 浅灰底

### 态度标签

五级标签：

- `积极`
- `中性偏积极`
- `中性`
- `中性偏消极`
- `消极`

HTML 颜色：

- 积极：绿色
- 中性偏积极：浅绿
- 中性：灰色
- 中性偏消极：琥珀/棕色
- 消极：红色

标签放在对应文本开头，不默认新增独立列。

### Next Step 倾向标签

具体行动项可以使用 pill：

```text
倾向：玩家分层名称
```

规则：

- 标签名称来自当前报告的玩家分类。
- `pending` 不加倾向标签。
- 标签必须与行动项同处一格，不新增列。

## 玩家原话层级

`玩家原话` 单元格要分层显示：

- `中文翻译：` 加粗或更深色
- `原文：` / `英文整理原文：` 正文色
- `来源：` 次级灰色

字号可小于正文，但不能低到看不清。证据之间用适度间距，不要一大坨。

## Appendix 评分表

Appendix 放在页面底部。

规则：

- 评分表必须保留数字。
- 必须有 `综合打分` 列。
- 玩家分层列按报告口径命名。
- 使用热力色：
  - 低分：浅红
  - 观察：浅黄
  - 正向：浅绿
  - 强正向：更深浅绿
  - 无数据：浅灰
- Appendix 不需要冗长说明。

## 多语言和本地化

当用户要求多语言：

- 右上角显示语言切换按钮。
- 默认中文。
- 默认语言集合可包含：`中文 / EN / VN / TH / ID / ES / PT`，但可按项目调整。
- 语言按钮必须链接到真实本地 HTML 文件，不能只是装饰。
- 每个语言页设置正确 `lang` 和 `data-locale`。
- 生成文件命名建议：
  - `*_CN.html`
  - `*_EN.html`
  - `*_VN.html`
  - `*_TH.html`
  - `*_ID.html`
  - `*_ES.html`
  - `*_PT.html`

本地化格式适配：

- 泰语：增加行高，允许自然断行。
- 越南语：注意重音字符和表头换行。
- 印尼语、英语、西语、葡语：允许长词换行，避免表头挤爆。
- 语言切换按钮在窄屏自动换行或变成 sticky 顶部控件。
- 玩家原文证据应尽量保留原文，不因本地化而丢失来源。

## 评论模式

当用户要求 HTML 报告支持协作评论时，默认加入轻量评论层：

- 右上角提供 `阅读模式` / `评论模式` 两个切换按钮。
- 默认进入 `阅读模式`，不显示评论气泡，不打扰阅读。
- 进入 `评论模式` 后显示所有评论气泡，并提示“点击页面任意位置添加评论”。
- 评论模式下点击正文任意位置弹出评论框，确认后发布，取消不保存。
- 点击已有评论气泡可编辑或删除。
- 评论气泡只显示短编号，内容放在弹出的编辑框中，避免压住正文。
- 评论控件必须支持多语言文案，至少覆盖中文、英语、越南语、泰语、印尼语、西语、葡语。
- 直接 `file://` 打开时可用 `localStorage` 本地保存，部署到服务器时应优先走 `/api/comments` 持久化。
- 评论数据按报告 `docId` 保存；多语言版本可以共用同一个基础 `docId`。
- 打印或导出 PDF 时隐藏评论控件和气泡。

评论层是审阅工具，不应改变正文结构、表格数据、Next Step 或证据内容。

## HTML 输出要求

- 输出单文件 HTML，CSS 内联。
- 普通阅读不需要启动 dev server，直接 `file://` 打开即可；多人评论同步需要通过服务器访问。
- 保留移动端响应式。
- 不改动已经确认的结论、反馈点、Next Step、PIC 和玩家原话。
- 如果生成本地化页面，先以当前确认版中文 HTML 作为母版。

## 视觉 QA

最终检查：

- 首屏标题区是否紧凑。
- 导航是否正确，没有多余 `关键发现`。
- `Next Step` 整列是否统一底色。
- 表格是否没有页面级横向溢出。
- `玩家原话` 是否清楚可读。
- 态度标签、频度标签、倾向标签是否有清晰颜色层级。
- `研发 PIC` / `运营 PIC` 是否存在。
- Appendix 评分是否有综合打分和热力色。
- 多语言按钮是否能打开对应文件。
- 各语言 `lang` / `data-locale` 是否正确。
