# FGD HTML 报告格式参考

用于把已经整理好的中文 FGD Markdown 报告转成可直接打开、可截图、可导出 PDF 的单文件 HTML。该格式来自越南玩家 FGD 报告的最终版。

## 适用场景

- 用户明确要求“做成好看的 HTML”“可视化报告”“网页报告”。
- 已经有结构完整的 FGD Markdown 报告。
- 最后一节仍需保持 `具体反馈建议` 的表格结构，而不是卡片结构。

## 信息结构

HTML 页面使用以下顺序：

1. 顶部品牌细线
2. 标题区
   - eyebrow：`Vietnam Player FGD / Gold & Glory` 或项目名
   - H1：报告标题
   - 一段简短说明
   - 3-4 个元信息标签，如 `Session 1：新玩家`、`Session 2：老玩家`、`中文报告版`、`含越南语原话证据`
3. 横向 sticky 导航
   - 项目背景
   - 核心结论
   - 关键发现
   - 新老玩家对比
   - 具体反馈建议
4. 执行摘要区
   - 左侧：一句话结论
   - 右侧：优先看这三件事
5. 正文报告
   - 保持 Markdown 报告原结构
   - 正文以文档流为主，不做 landing page 式 hero
6. 具体反馈建议
   - 必须保持表格
   - 表头固定为：`反馈模块 | 提及频度 | 反馈点 | 建议 | 玩家原话`

## 视觉系统

使用 fastpublish `slide-maker` skill 中 Garena preset 的配色，不使用渐变。

```css
:root {
  --brand-primary: #C0504D;
  --brand-secondary: #997E5A;
  --brand-dark: #4D4D4D;
  --brand-medium: #7F7F7F;
  --brand-light: #BFBFBF;
  --brand-bg: #E9D7D3;
  --brand-bg-alt: #F5F0EE;
  --brand-white: #FFFFFF;
  --brand-black: #333333;
}
```

页面基调：

- 页面底色：纯 `#F5F0EE`
- 内容底色：白色
- 重点色：深红 `#C0504D`
- 辅助色：铜金 `#997E5A`
- 正文色：炭灰 `#4D4D4D`
- 分割线：暖灰/浅灰 `#BFBFBF` 或浅化版本

禁用：

- 不使用 `linear-gradient`
- 不使用 `radial-gradient`
- 不使用大面积彩色背景
- 不使用装饰性光斑、气泡、bokeh、浮夸阴影
- 不把研究报告做成 marketing landing page

## 字体

优先使用 Garena preset 的 serif 风格：

```css
@import url('https://fonts.googleapis.com/css2?family=EB+Garamond:wght@500;600;700;800&family=Noto+Serif+SC:wght@400;500;600;700&display=swap');

:root {
  --font-display: 'EB Garamond', 'Noto Serif SC', 'Garamond', 'Georgia', serif;
  --font-body: 'EB Garamond', 'Noto Serif SC', 'Garamond', 'Georgia', serif;
}
```

如果外网字体不可用，回退到本地 serif 字体即可。中文报告应保证中文显示稳定，不牺牲可读性。

## 布局规则

- 页面最大宽度建议 `1160px` 左右。
- 标题区要紧凑，首屏必须能看到正文开头或执行摘要，不要做巨大空白 hero。
- 导航采用横向 sticky nav，不使用左侧大目录，避免报告显得像网页后台。
- 正文使用白底报告容器，轻边框、轻阴影即可。
- 章节标题使用圆形编号，但要克制，不要过大。
- 执行摘要可以使用两个并列面板；其他正文不要过度卡片化。

## 表格规则

正文对比表：

- 保持标准表格。
- 表头使用浅暖底 `--brand-bg-alt`。
- 第一列可用品牌主色加强扫描。

`具体反馈建议` 表：

- 必须保持表格结构。
- 桌面端允许横向滚动，但不要撑破页面。
- 建议最小宽度约 `1180px`。
- 推荐列宽：
  - `反馈模块`: 112px
  - `提及频度`: 84px
  - `反馈点`: 235px
  - `建议`: 285px
  - `玩家原话`: 464px
- `提及频度` 用 pill 标签：
  - 高频：深红字 + 浅红底
  - 中频：铜金字 + 浅金底
  - 低频：灰/蓝灰字 + 浅灰底
- `建议` 列可以用左侧铜金线强调。
- `玩家原话` 单元格要分层显示：
  - `中文翻译：` 加粗或更深色
  - `越南语原文：` 正常正文色
  - `来源：` 使用次级灰色

## HTML 输出要求

- 输出单文件 HTML，CSS 内联。
- 不需要启动 dev server，直接 `file://` 打开即可。
- 保留移动端响应式：正文单列，表格在表格容器内横向滚动。
- 不要改动 Markdown 报告里的结论、反馈点、建议和玩家原话。
- 如果要生成截图检查，至少检查：
  - 首屏标题和执行摘要
  - 正文 `核心结论`
  - 最后一节 `具体反馈建议` 表格
  - 移动端是否没有页面级横向溢出

## 推荐页面文案

标题区说明可使用：

```text
基于[市场/地区]两场玩家 FGD 逐字稿整理，重点看新玩家的可读性门槛、老玩家对硬核感的担忧，以及镜头、操作、锁敌、格挡、职业、UI、氛围和 PvE 的产品反馈。
```

执行摘要默认：

```text
一句话结论：
[市场/地区]玩家对题材和组队体验有明确兴趣，但新版需要在“新手看得懂”和“老玩家仍觉得危险、有技术表达”之间重新找平衡。
```

优先看三件事示例：

- 操作、锁敌、血条、技能指示会直接影响新玩家留存。
- 镜头过宽、自动化和通用格挡会削弱老玩家在意的压迫感。
- PvE 需要从刷资源通道升级为有挑战和复玩动力的模式。
