# FGD 报告格式参考

用于将玩家 FGD、访谈逐字稿、研究笔记整理成中文产品研究报告。默认格式来自越南玩家 FGD 报告。

## 标准结构

```markdown
# [市场/对象] FGD 研究报告

## 1. 项目背景

## 2. 核心结论

## 3. 关键发现
### 3.1 初始吸引力
### 3.2 镜头视角与可见性
### 3.3 操作控制与战斗手感
### 3.4 闪避/位移与战斗节奏
### 3.5 锁敌与自动瞄准
### 3.6 格挡/招架与武器防御
### 3.7 职业与角色设计
### 3.8 UI 与战斗信息
### 3.9 美术、音效与氛围
### 3.10 PvE / 地图 / 模式体验（补充观察）

## 4. 新玩家与老玩家对比

## 5. 具体反馈建议
```

按项目实际情况调整 3.x 小节，不要机械保留无材料支撑的章节。

## 研究目标优先级

先识别本次 FGD 的主要研究目标，再决定报告排序和建议优先级。

如果用户说明本次 FGD 主要调研 `3C / 战斗相关体验`，报告应优先覆盖：

1. 镜头视角与可见性
2. 操作控制与战斗手感
3. 闪避/位移与战斗节奏
4. 锁敌与自动瞄准
5. 格挡/招架与武器防御
6. 职业战斗定位
7. UI 与战斗信息

PvE、美术音效、社交、整体吸引力、继续游玩意愿等可以保留，但应标注为补充观察，不要压过 3C 战斗主轴。

注意区分 `提及频度` 和 `产品优先级`：

- `提及频度` 只表示玩家提到的密度。
- `产品优先级` 由本次研究目标决定。
- 当用户明确 3C 是主目标时，最终反馈建议表可以优先按 3C 战斗链路排序，再参考提及频度；PvE 即使有多名玩家提到，也应放在补充位置。

## 各章节写法

### 1. 项目背景

写清：

- 市场/地区
- 场次数量
- 玩家分组
- 研究对象和版本
- 讨论覆盖范围

示例语气：

```text
本次研究基于越南市场两场玩家 FGD 逐字稿：
- Session 1：新玩家组……
- Session 2：老玩家组……
两场讨论围绕 Gold & Glory 的新版本体验展开，重点覆盖……
```

### 2. 核心结论

用 2-4 段给出总判断。

必须包含：

- 产品是否有吸引力
- 新玩家和老玩家的核心差异
- 最大产品矛盾
- 最优先的产品方向

写法要直接：

```text
越南玩家对产品存在明确兴趣，核心吸引力来自……

但当前版本面临明显的新老玩家分化：
- 新玩家更关注……
- 老玩家更关注……

总体判断：……
```

不要单独增加“总结”章节；把总结观点并入核心结论。

### 3. 关键发现

用短段落和少量 bullet 描述主题发现。每个主题建议包含：

- 新玩家怎么看
- 老玩家怎么看
- 关键结论/产品含义

示例：

```text
新玩家整体可以接受第三人称视角，但反馈画面信息较乱……

老玩家对视角更敏感。部分玩家认为当前视角过宽……

关键结论：视角应提供可调节选项……
```

不要在关键发现里堆原话。原话放到最后的“具体反馈建议”表中。

### 4. 新玩家与老玩家对比

使用中文表头：

| 维度 | 新玩家 | 老玩家 |
| --- | --- | --- |
| 核心动机 | 题材、角色、组队、移动端便利 | 机制深度、旧版记忆、竞技表达、社区玩法 |
| 主要阻碍 | 看不懂、按不顺、信息混乱 | 过于简单、失去紧张感、职业同质化 |
| 镜头偏好 | 更容易观察即可 | 不宜过宽，应保留压迫感 |
| 锁敌/自动瞄准 | 需要辅助，但要更智能 | 担心降低技术含量 |
| 闪避/位移 | 需要好按、距离清楚、冷却好理解 | 应按职业区分距离、冷却和接近/脱身价值 |
| 格挡/招架 | 需要明确成功反馈和反击提示 | 不同武器/盾牌/法杖不应拥有同质化强格挡 |
| 战斗期待 | 清楚、容易上手、有反馈 | 有风险、有反制、有职业弱点 |
| 美术期待 | 好看、清晰、角色吸引人 | dark fantasy、地牢压迫、旧版氛围 |
| PvE 期待（补充） | 非本次重点 | 更难、更多随机、Boss、奖励驱动，但优先级低于 3C 战斗体验 |

根据实际材料增删维度。

### 5. 具体反馈建议

这是报告里的产品建议和证据汇总，不再另设“产品建议”章节。

表格字段固定为：

| 反馈模块 | 提及频度 | 反馈点 | 建议 | 玩家原话 |
| --- | --- | --- | --- | --- |

字段写法：

- `反馈模块`: 如 操作/技能、镜头/视野、闪避/位移、锁敌/自动瞄准、格挡/招架、职业/角色、UI/战斗信息、整体吸引力、社交/组队、地图/PVE（补充）、美术/氛围、音效/战斗信息、社区功能。
- `提及频度`: 高 / 中 / 低。
- `反馈点`: 一句话描述玩家反馈，不要写成建议。
- `建议`: 一句话或一小段产品动作，必须和反馈点直接相关。
- `玩家原话`: 必须包含中文翻译、原文、来源。

玩家原话格式：

```text
中文翻译：……
越南语原文：“……”
来源：Session 1, line 1291
```

## 排序规则

默认情况下，`具体反馈建议`表按提及频度排序：

1. 高频
2. 中频
3. 低频

同一频度内按产品逻辑排序：

1. 吸引力/动机
2. 社交/组队
3. 镜头/视野
4. 操作/技能
5. 闪避/位移
6. 锁敌/自动瞄准
7. 格挡/招架
8. 职业/角色
9. UI/战斗信息
10. 美术/氛围
11. 音效/战斗信息
12. 地图/PVE（补充）
13. 社区功能

如果用户明确 3C/战斗是研究主目标，则最终表优先按研究目标排序：

1. 3C/战斗模块：镜头、操作、闪避/位移、锁敌、格挡/招架、职业战斗定位、UI/战斗信息
2. 整体吸引力、社交/组队、美术/氛围、音效
3. PvE / 地图 / 模式体验（补充）
4. 社区功能或其他低频补充项

## 合并规则

合并重复或近似反馈：

- 如果两个点只是“现象”和“接受度”不同表达，合并。
  - 例如“通用格挡削弱突袭”和“玩家喜欢视觉但不认可机制平衡”可合并为：
    `格挡表现受欢迎，但“全职业通用格挡”会削弱伏击、刺客和近战切入价值。`
- 如果两个点对应不同产品动作，保留为不同条目。
  - 例如 `PvE 难度过低` 与 `PvE 缺少复玩动力` 可保留分开：前者对应难度/事件，后者对应目标/奖励/循环。
- 不要合并 `格挡/招架` 和 `闪避/位移`。
  - `格挡/招架`: 指武器、盾牌、法杖/书本等防御动作、防御判定、parry 成功反馈。
  - `闪避/位移`: 指每个职业都有的小位移，如 dash/dodge/翻滚，关注距离、冷却、硬直、接近/脱身价值。

## 证据覆盖检查

最终检查：关键发现中的每类反馈是否都在“具体反馈建议”中有证据。

特别检查以下常漏项：

- UI/血条：敌我、玩家/怪物、血量百分比是否清楚
- 低血提示是否占屏
- 小地图/路线引导是否直观
- 脚步声方向、距离、敌我来源是否清楚
- 锁敌是否误锁怪物
- 定向技能是否有落点/范围提示
- 闪避/位移是否按职业区分距离、冷却和接近/脱身价值
- 格挡/parry 成功反馈是否清楚，盾牌/武器/法杖格挡是否同质化
- 法师、战士、辅助等职业是否有证据支持
- PvE 是否作为补充观察处理；如果本次研究主目标是 3C，不要让 PvE 结论盖过战斗体验结论

## 语言风格

- 用中文标题。
- 用短段落，不堆长篇解释。
- 先讲发现，再讲原因或含义。
- 不要写“Methodology/分析方法”，除非用户要求。
- 不要写“策略启示”，除非用户要求。
- 不要在最后表格前加冗长说明。
- 不要把所有建议集中成单独章节。
- 不要在每段都写“关键结论：”，只在需要收束时使用。
- 避免 AI 腔：少用“综上所述”“值得注意的是”“多维度”“赋能”等空泛词。

## 文件输出

默认输出为 Markdown，除非用户要求 PPT/PDF/DOCX。

文件命名建议：

- 中文报告：`[市场/地区]_FGD_研究报告_CN.md`
- 如需 PDF：先生成可编辑 HTML，再渲染 PDF。
